# 10 · 运行、构建与测试

## 1. 环境要求

| 项 | 要求 |
| ---- | ---- |
| 操作系统 | 开发/运行：Windows 10/11（64 位）；打包 Windows 目标在 Linux/mac 需 `wine`，建议直接在 Windows 发布 |
| Node.js | 与 Electron 31 配套（建议 Node 18+） |
| 包管理 | npm（有 `package-lock.json`） |

## 2. 安装与启动

```bash
npm install        # 安装依赖
npm start          # = electron .   启动开发态应用
```

开发态数据目录为仓库根 `data/`（见 [02-主进程 §1.1](02-主进程.md#11-数据目录解析-resolvedatadir)）。

## 3. npm 脚本

来自 [package.json](file:///workspace/package.json)：

| 脚本 | 命令 | 作用 |
| ---- | ---- | ---- |
| `start` | `electron .` | 启动应用 |
| `test` | `node --test "tests/**/*.test.js" && node tools/regress.test.js` | 跑全部 `node:test` 单测 + 轻量回归 |
| `verify` | `node tools/wiring-audit.js && node tools/scan-thirdparty.js && node tools/regress.test.js && node tools/dice-regression.js` | 发布前校验：接线审计 + 零第三方扫描 + 回归 + 骰娘全指令回归 |
| `bench` | `node tools/perf-bench.js` | 性能基准（检索热路径等） |
| `build` | `npm run build:portable && npm run build:green` | 一键产出便携版 exe + 绿色版 zip（发布唯一入口） |
| `build:dir` | `electron-builder --win dir --publish never` | 免安装目录（绿色版素材，被 `build:green` 内部调用） |
| `build:dir:release` | `RELEASE_TYPE=正式版 … --win dir` | 正式版目录构建 |
| `build:portable` | `RELEASE_TYPE=便携版 … --win portable --publish never` | 打包便携版 |
| `build:green` | `build:dir` 后经 `node tools/package-green.js` 压缩 | 打包绿色版 zip |
| `publish:github` | `bash tools/publish-github.sh` | 一键发布到 GitHub Releases |

> **发布规定**：只制作并发布绿色版 + 便携版，不再提供安装版（无 `build:installer`）。

## 4. 构建产物与发布

| 命令 | 产物 | 形态 |
| ---- | ---- | ---- |
| `npm run build` | `dist/KP跑团工作台_v<版本>_便携版.exe` + `dist/KP跑团工作台_v<版本>_绿色版.zip` | 便携版 + 绿色版 |
| `npm run build:portable` | `dist/KP跑团工作台_v<版本>_便携版.exe` | 便携版 |
| `npm run build:green` | `dist/KP跑团工作台_v<版本>_绿色版.zip`（顶层目录 `KP跑团工作台_v<版本>_绿色版/`） | 绿色版 |

electron-builder 关键配置（[package.json](file:///workspace/package.json) 的 `build`）：`asar: true`、`electronVersion 31.7.7`、`electronDist .ecache`、输出到 `dist/`、资源目录 `build/`、`npmRebuild: false`、`signAndEditExecutable: false`。

一键发布：

```bash
GH_TOKEN=<Contents:write 令牌> bash tools/publish-github.sh          # 发布 dist 中所有版本
GH_TOKEN=xxx bash tools/publish-github.sh 3.1.2                      # 只发指定版本
GH_TOKEN=xxx bash tools/publish-github.sh --dry-run                  # 只打印动作
```

- Release 正文由 [tools/release-notes.js](file:///workspace/tools/release-notes.js) 从 `app.js` 的 `CHANGELOG` 生成。
- 附件名统一 ASCII：`KP-workbench-vX.Y.Z-green.zip` / `-portable.exe`（仅这两种，中文附件名会被 GitHub 规范化导致撞名）。
- Release 必须是 **latest 正式版**，不要勾选 Pre-release。
- 脚本可重复执行：已存在 Release 刷新正文，已上传附件跳过，缺失补传。

发版前务必先提升版本号并同步 `app.js` 的 `APP_VERSION` / `CHANGELOG`，详见 [DEPLOY.md](file:///workspace/DEPLOY.md) 与 [08-自动更新机制 §9](08-自动更新机制.md#9-发布前检查)。

### 5.2 命令

```bash
npm test        # 全部单测 + tools/regress.test.js
npm run verify  # 接线审计 + 零第三方扫描 + 回归 + 骰娘全指令回归
```

`preload-contract.test.js` 校验 preload 与主进程契约；`build-config.test.js` 校验 `package.json` 与 `app.js` 的版本一致等；`regression-script.test.js` 把 `tools/dice-regression.js` 的用例接入 `node:test`。

## 6. 工具链（tools/）

| 工具 | 作用 |
| ---- | ---- |
| [wiring-audit.js](file:///workspace/tools/wiring-audit.js) | 接线审计：IPC 通道、`window.api.*`、`window.WB`、重复函数/id、`q('id')` 引用、内联事件裸调用 |
| [scan-thirdparty.js](file:///workspace/tools/scan-thirdparty.js) | 零第三方残留扫描：`resources/dice-next/`、`bridge/*` 不存在；`src/` 与 `package.json` 不含关键字 `dice-next` / `sd-api` / `sealdice` / `lagrange` / `milky` |
| [regress.test.js](file:///workspace/tools/regress.test.js) | 轻量回归：从 `app.js` 抽取顶层纯函数，在无 DOM / 无 Electron 下验证关键不变量（每条用例对应一次真实缺陷） |
| [dice-regression.js](file:///workspace/tools/dice-regression.js) | 骰娘全指令回归：用 `CommandBrain.handle` 跑指令①②③④全量用例，接入内存桩与零第三方扫描 |
| [perf-bench.js](file:///workspace/tools/perf-bench.js) | 性能基准（资料检索/全局搜索热路径） |
| [release-notes.js](file:///workspace/tools/release-notes.js) | 从 `app.js` 的 `CHANGELOG` 生成 Release 正文 |
| [publish-github.sh](file:///workspace/tools/publish-github.sh) | 一键发布到 GitHub Releases；从 `git remote origin` 推断仓库 |
| [fake-onebot.js](file:///workspace/tools/fake-onebot.js) | 假 OneBot 协议端，用于本地联调通道 |

## 7. 本地联调

- **应用内测试通道**：侧栏「骰娘工作台 → 应用内测试通道」可直接跑全部指令，无需联网（对应 `dice-net/sim`）。
- **假协议端**：`node tools/fake-onebot.js` 配合 OneBot 11 通道联调。
- **骰娘调试页**：浏览器打开 [src/renderer/test_dice.html](file:///workspace/src/renderer/test_dice.html)。
- **运行记录**：应用内「更多工具 → 运行记录」查看/导出 `data/runlog/latest.log`，排查问题可直接提供该文件。

## 8. 常见问题定位

| 现象 | 排查方向 |
| ---- | ---- |
| 界面按钮点击报「不是函数」 | 该类问题已由 `wiring-audit` 拦截；检查 `window.WB` / `window.api` 是否挂载 |
| AI 请求无反应 | 检查 AI 开关（总开关 + 分开关）、`baseUrl/apiKey/model` 是否配置；`ai:busy` 是否有广播 |
| AI 提示「正在处理」 | 同类型任务已在飞（`aiGuard` 同组互斥）；可等待或 `aiCancel(group)` 取消 |
| 数据损坏提示恢复 | `DataStore.load` 的自愈链（备份/快照）；检查 `backups/kp-data.corrupt-*.json` 留证 |
| 更新检测失败 | 多为 GitHub API 限流；确认 owner/repo 常量、代理/镜像前缀配置 |
| 骰娘连不上 | 「连接中心」看 `lastError`；OneBot 检查端口/令牌/协议端；QQ 官方检查 `appId/clientSecret` 与网关关闭码 |
