# 07 · AI 能力集成

AI 是本项目的重要能力：资料生成与拆分、剧本分幕与全文写作、记录润色、关系补全、地图草稿、骰娘增强、KP 建议等。所有 AI 调用都经**统一的开关体系、提示词中枢与请求守卫**，确保「未放行就不消耗 token」。

AI 采用 **OpenAI 兼容接口**，用户在「AI 配置」页填写 `baseUrl` / `apiKey` / `model`，数据只发往用户自配的端点。

## 1. 模块构成

| 文件 | 职责 |
| ---- | ---- |
| [ai.js](file:///workspace/src/main/ai.js) | 工作台 AI 核心：人设/字段 schema、OpenAI 兼容调用、剧本→结构化解析、提示词注入 |
| [prompt-hub.js](file:///workspace/src/main/prompt-hub.js) | 提示词中枢：总提示词 + 场景模板 + 分场景记忆文件 |
| [dice-ai.js](file:///workspace/src/main/dice-ai.js) | 把工作台主 AI 包装为骰娘引擎的 `AiPort`，统一开关判定 |
| [dice-enhance.js](file:///workspace/src/main/dice-enhance.js) | 骰点文本润色 + 随机插话（回复增强） |
| [dice-kp-advice.js](file:///workspace/src/main/dice-kp-advice.js) | KP 带团建议（聚合对局上下文，面板内生成，不对外发送） |
| [dice-memes.js](file:///workspace/src/main/dice-memes.js) | 表情包库：收录/打标签/随机调用 |
| `renderer` 的 AI 视图 | AI 助手、AI 设定、AI 配置、记录润色、群聊 AI 行为等界面 |

## 2. 统一 AI 开关体系

配置位于 `settings.ai`（[main.js](file:///workspace/src/main/main.js) 初始化时补默认值）：

| 字段 | 说明 |
| ---- | ---- |
| `enabled` | **总开关**；`false` 时所有 AI 请求一律拒发 |
| `features` | 按功能分开关：`dice` / `optimize` / `interject` / `meme` / `kpAdvice` |
| `interjectProb` | 随机插话命中率（%，默认 15） |
| `memeProb` | 插话时附带「偷来的表情」的概率（%，默认 25） |
| `optimizePrompt` | 骰点优化附加提示词 |

判定集中在 [dice-ai.js](file:///workspace/src/main/dice-ai.js)：总开关关闭 → 拒发；分开关关闭 → 拒发并返回友好文案（`FEATURE_OFF_TEXT`）；AI 未配置（未填连接/密钥/模型）→ 直接短路，绝不尝试调用供应商。因此骰娘引擎与各增强功能在未放行时只「多花在文案」，不产生真实请求。

工作台侧另有 `ai:switchesGet` / `ai:switchesSet` 供界面读写开关。

## 3. 提示词中枢 prompt-hub

用于解决「提示词散落各处、长期记忆只能全量注入」的问题，做三件事（[prompt-hub.js#L2-L23](file:///workspace/src/main/prompt-hub.js#L2-L23)）：

1. **场景注册表**：把所有会调 AI 的场景登记为 `key → 提示词模板`（系统/用户）。`DEFAULT_SCENES` 覆盖工作台与骰娘各场景（`chat` / `persona` / `entities` / `registration` / …）。
2. **总提示词（master）**：`settings.prompts.master`，所有场景每次运行都会注入。
3. **分场景记忆文件**：每场景一个记忆文件 `data/memories/<key>.md`，运行前只注入**本场景记忆尾部**（而非全量长记忆），运行后可回写要点，减少无关上下文、节省 token、聚焦当前场景。

后端契约：

```js
list()                            // 场景元信息列表（供设置界面编辑）
effective(settings)               // 每个场景生效提示词（默认｜覆盖）
masterOf(settings)                // 取总提示词
systemFor(scene, settings, vars)  // system = 总提示词 + 场景系统提示 + 场景记忆
userFor(scene, settings, vars)    // 用户提示（场景覆盖则用它，否则用调用方默认）
Memory: read / append / filePath / listMemories / clear
```

`ai.js` 通过 `setHubContext({ dataDir })` 注入数据目录，并用 `hubPrefix` / `hubSystem` 把「总则 + 场景记忆」拼到既有 system 之前；**未注入时一律返回空字符串**，不影响单测与离线行为。

对应 IPC：`promptHub:*` 一组（见 [02-主进程 §3.5](02-主进程.md#35-提示词中枢-prompthub)）。

## 4. AI 请求守卫与任务队列

渲染层与主进程两侧共同保证不重复调用、可取消：

### 4.1 渲染层 `aiGuard`（[preload.js](file:///workspace/src/preload.js)）

- 按「任务类型」分队列：同类型一次只放行一项，未完成时同类型再调用被拦下并说明；不同类型可并行。
- 任务类型 → 组：`AI_GROUPS`（`chat` / `cards` / `scenario` / `map` / `tpl` / `sys`）。
- 请求开始/结束广播 `ai:busy`，界面统一显示「AI 处理中」（含任务类型）；`aiCancel(group)` 可取消某组在飞请求。

### 4.2 主进程取消与用量

- `ipcMain.on('ai:cancel', …)`：中止对应在飞请求。
- `ai:usage` / `ai:usageReset`：读取/重置本轮用量（token + 耗时）。
- `ai:switchesGet` / `ai:switchesSet`：开关读写。

## 6. 骰娘 AI 增强

- **`dice-ai.js`**：`createDiceAi({ ai, getContext(feature) })` 返回骰娘 `AiPort`。走 `chatRaw` 完整保留含 system 的消息序列，不注入工作台人设，让骰娘用自身 persona 发声；仍复用超时/取消/内容安全收口。
- **`dice-enhance.js`**（`transformReplies`）：
  - 骰点文本优化：命中 `r/rd/ra/rh` 时结合场景润色结果。
  - 随机插话：按概率追加骰娘插话。
  - 安全校验 `acceptableOptimize`：AI 追加描述必须与引擎数值一致；拒绝「索要结果」话术与夹带伪指令；引擎原文永远先发、不被改写。失败不炸指令。
- **`dice-kp-advice.js`**：聚合当前对局上下文生成带团建议，仅面板展示、不对外发送。
- **`dice-memes.js`**：表情包库查询/收录/打标签/随机调用。
- **`diceCore:aiChat`**：骰娘独立 AI 端口（OpenAI 兼容），供投骰台 AI 定向判定独立调用，不依赖工作台全局 AI。

## 7. 卡片模板

`ai.BUILTIN_TEMPLATES`（内置 CoC/DnD 规则书模板）在 [main.js](file:///workspace/src/main/main.js) 初始化时注入 `settings.templates`；用户自建模板保留，内置模板按 id 去重补齐。支持编辑/另存为模板、AI 依据规则书生成模板、AI 多卡提取勾选写入。

## 8. OpenAI 兼容调用约定

- 端点、密钥、模型来自 `settings.ai`（或骰娘独立端口 `diceCore:aiChat` 的入参 `cfg`）。
- `.ai` 指令与各增强功能均经 `AiPort` 统一入口 → 受开关约束。
- 长任务支持超时与取消；大文件分析分块处理并广播进度。
- 内容安全：内容过滤规则可编辑（`modRuleDefaults` / `mod` 指令）。
