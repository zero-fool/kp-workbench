## 2. 内部模块分层与依赖方向

```
renderer ──(window.api / window.diceCore)──▶ preload ──(IPC)──▶ main
                                                                 │
                          ┌──────────────────────────────────────┤
                          ▼                    ▼                  ▼
                    dice-core              dice-net          updater/exporter
                  (纯 Node 内核)         (纯 Node 通道)      (纯 Node，可单测)
                          ▲                    ▲
                          └──────── ports ◀────┘
                              (契约层)
```

规则：

- **单向依赖**：上层依赖下层，禁止反向。渲染层不得直接 `require` Node 模块。
- **内核与通道互不依赖**：二者只通过 `dice-core/ports` 的契约（MessageIn / ReplyOut / ChannelAdapter / StorePort / AiPort）协作，由 `dice-core/hub` 装配。
- **可测试性**：`dice-core` / `dice-net` / `updater` 不 `require('electron')`，可在纯 Node 下跑 `node:test`。

## 4. 契约抽象（ports）

`dice-core/ports` 是内核与外部（通道、主进程、测试）之间的**唯一契约面**：

| 契约 | 提供方 | 实现方 |
| ---- | ---- | ---- |
| `MessageIn` / `ReplyOut` | `ports/message` | 各通道 normalize |
| `ChannelAdapter` | `ports/channel`（`assertChannel`） | `dice-net` 的 sim / onebot11 / qqofficial |
| `StorePort` | `ports/store`（`createMemoryStore`） | 主进程 `dice-state-store` 的 `createMainStorePort` |
| `WorkspaceDataPort` | `ports/workspace`（`createMemoryWorkspace`） | 主进程 workspace IPC 端口 |
| `AiPort` | `ports/ai`（`createOfflineAi`） | 主进程 `dice-ai` 的 `createDiceAi` |

**内存实现**（`createMemory*` / `createOfflineAi`）用于单测与离线降级：内核在无主进程时也能独立运行（`createHub` 缺省即用内存 Store/Workspace 与离线 AI）。

## 5. 前后端契约（IPC）

`preload.js` 暴露的 `window.api` 与主进程 `ipcMain.handle/on` 构成前后端契约。契约完整性由 [tools/wiring-audit.js](file:///workspace/tools/wiring-audit.js) 校验，覆盖：

- IPC 通道：preload 的 `invoke` ↔ 主进程的 `handle` 双向对齐；
- `window.api.*` 暴露 ↔ 渲染层使用；
- `window.WB` 定义 ↔ 引用；
- 重复函数定义、重复 DOM id、`q('id')` 引用、内联事件裸调用。

任何一处断裂都会在 `npm run verify` 中报错，防止「调用了不存在的接口」这类低级 bug 上线。

## 6. 数据与配置依赖

- 数据模型由 [DataStore](file:///workspace/src/main/store.js) 的 `emptyData()` 定义（`version: 3`），分片落盘见 [06](06-数据存储与持久化.md)。
- 应用版本双处一致：`package.json.version` ↔ [app.js](file:///workspace/src/renderer/app.js) 的 `APP_VERSION`（`npm test` 校验）。
- 更新仓库常量：[github.js](file:///workspace/src/main/updater/github.js) 的 `OWNER` / `REPO` 需与 `tools/publish-github.sh` 推断的仓库一致。
