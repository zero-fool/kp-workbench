# 06 · 数据存储与持久化

数据层由 [store.js](file:///workspace/src/main/store.js) 的 `DataStore` 类统一实现，负责读写、分片、档案、备份与快照。所有数据落在本地 `data/` 目录，**不上传、不经第三方服务器**。

## 1. 目录布局

```
data/
├─ kp-main/                 # 分片档案（默认主档案）：目录名 kp-<archiveName>
│  ├─ _meta.json            # 元信息（不含 entities）：version/profiles/relations/settings/audit/maps...
│  ├─ pcs.json              # 人物卡
│  ├─ npcs.json             # NPC
│  ├─ regions.json          # 地区
│  ├─ logs.json             # 日志
│  ├─ mobs.json             # 怪物
│  ├─ rules.json            # 规则
│  ├─ lore.json             # 背景
│  └─ encounters.json       # 遭遇（临场战斗）
├─ kp-<其它档案>/            # 其它档案（多档案互不干扰）
├─ kp-data.json             # 主档案旧整档文件（首次加载后迁移为 kp-main/）
├─ kp-data.json.legacy      # 迁移后的旧文件留存
├─ backups/                 # 备份：kp-backup-<时间戳>.json、旧格式 kp-legacy-*.json、损坏留证 kp-data.corrupt-*.json
├─ snapshots/               # 自动版本快照：snap-<时间戳>.json（仅保留最近 N 份）
└─ maps/                    # 外置底图（base64 → .img 文件，避免主文档膨胀）
```

## 2. 数据模型

`emptyData()`（[store.js#L17-L28](file:///workspace/src/main/store.js#L17-L28)）定义文档结构：

```js
{
  version: 3,
  entities: { pcs, npcs, regions, logs, mobs, rules, lore, encounters },  // 各为数组
  fields: null,          // 自定义字段 schema；null 用内置默认
  profiles: [],          // AI 角色卡
  relations: { nodes: [], edges: [] },  // 关系网（节点 + 带标签连线）
  settings: {},          // 主题/布局/活动角色/档案名/自动备份/AI 开关/提示词等 UI 与策略偏好
  audit: [],
  created: ISOString
}
```

**资料类型 `KIND_LIST`**：`pcs / npcs / regions / logs / mobs / rules / lore / encounters`（中文名映射见 `NAME`）。
注意：`encounters`（遭遇）参与持久化与计数，但不在「资料卡网格 / 全局搜索 / 关系网」中显示。

## 3. 分片存储（Sharded）

大档案若整档读写会很慢，因此采用**按类型分片**：

- 每个实体类型写一个 `kp-<name>/<kind>.json`，元信息写 `_meta.json`（不含 `entities`）。
- 写入时对每个 kind 计算内容哈希（`_entityHashes`），**内容未变的类型跳过写入**（增量）。
- 读取时逐 kind 加载并对缺失/损坏的 kind 回退为空数组，不因单文件损坏影响整体。

### 旧格式自动迁移 `_migrateToSharded(d)`

`load()` 读到旧整档 `kp-data.json` 时：

1. 先把旧文件复制到 `backups/kp-legacy-<ts>.json` 留底；
2. 写出各分片文件与 `_meta.json`；
3. 把旧文件重命名为 `kp-data.json.legacy`；
4. 后续读写都走分片目录。

## 4. 原子写与写盘保护

`write(d)` / `_writeShardFile(kind, target, content)`：

- **原子写**：先写 `<file>.tmp`，再 `rename` 覆盖目标，避免中途断电产生半截文件。
- **失败留存**：写失败时把内容存为 `<file>.failed-<ts>.tmp` 现场留证，并把错误挂到 `_lastWriteError` / `_writeFailedKinds`，上层可经 `lastWriteError()` 感知（返回 `{ok, error, kinds}`）。
- **外置底图**：`maps[].img` 为 `data:` base64 时，写入 `maps/<hash>.img`，文档中改存 `$IMG_FILE:<hash>.img` 标记；读取时回填。避免 base64 撑大主文档。

## 5. 档案（Archive）

| 方法 | 说明 |
| ---- | ---- |
| `listArchives()` | 扫描 `data/` 下的分片目录（`kp-<name>/` 含 `_meta.json`）与整档文件，返回档案列表 |
| `createArchive(name)` | 新建档案 |
| `duplicateArchive(name)` | 复制档案 |
| `deleteArchive(name)` | 删除档案 |
| `switchTo(name)` | 切换当前档案，重置分片目录与哈希缓存 |

扫描时**显式跳过主文件 `kp-data.json`**，否则会被 `kp-*.json` 正则误判出名为 `data` 的幽灵档案，选中后引发冲突卡死。

## 6. 备份（Backup）

- `backup()`：把当前文档写入 `backups/kp-backup-<时间戳>.json`。窗口关闭前（`win:close`）会触发一次。
- `listBackups()` / `restore(fileName)`：列出与回滚。
- 自动备份间隔由 `settings` 控制（`autoBackupMinutes()` / `lastBackupAt()`），主进程按间隔轮询，复用内存态缓存 `_doc` 避免周期性整档读盘。

## 7. 快照（Snapshot，版本回滚）

- `maybeSnapshot(d)`：每次内容变更后沉淀一份快照，用于「数据自动版本快照 + 一键回滚」。
- 去重与节流：内容哈希（`_lastSnapHash`）未变则不写；两次快照至少间隔 8 秒（`_lastSnapTs`）。
- `listSnapshots()` / `restoreSnapshot(fileName)`：列出与回滚；旧快照按保留份数上限清理（默认最近 40 份）。

## 8. 读档自愈

`load()` 解析失败时的自愈链（[store.js#L337-L351](file:///workspace/src/main/store.js#L337-L351)）：

```
JSON 解析失败
  ├─ 把损坏文件复制到 backups/kp-data.corrupt-<ts>.json 留证
  ├─ tryNearestRestore()：依次尝试最近可用备份 / 快照
  │    └─ 命中 → 写回 → 标记 _recoveredFrom = 'backup' | 'snapshot'
  └─ 都失败 → 重置为空文档（emptyData）并写盘
```

`_recoveredFrom` 供上层提示「已从备份/快照恢复」。

## 9. 存储类型与 CRUD

- `crud(kind, op, item)`：对指定资料类型的增删改统一入口。
- `meta()`：返回各类型计数（`pcs/npcs/...` 条数），供总览看板与统计分析。
- `uid()`：`crypto.randomBytes(8).toString('hex')` 生成 id。
- `quickHash(s)`：轻量字符串哈希，用于去重与增量判断。

## 10. 骰娘数据持久化

骰娘状态复用 DataStore 的写入与备份机制，由 [dice-state-store.js](file:///workspace/src/main/dice-state-store.js) 的 `createMainStorePort(dataStore)` 实现 StorePort：

```js
{ load(key), save(key, value), backup() }
```

允许的持久化键（`KEYS`）：`dice-state` / `dice-replies` / `dice-drew` / `dice:sessions` / `dice-memes`。传入未知键会抛 `TypeError`。`save` 走该键值的更新 + `DataStore.write`（原子写 + 快照去重）。

## 11. 数据目录与迁移

数据目录按运行形态解析，见 [02-主进程 §1.1](02-主进程.md#11-数据目录解析-resolvedatadir)。要点：

- 安装版首次运行会把 exe 旁的旧 `data/` 自动迁移到用户目录（`autoMigrateLegacyData`）。
