# 02 · 主进程（src/main）

主进程是应用的编排中枢：唯一可访问文件系统、网络、子进程的进程，负责窗口生命周期、全部 IPC 注册、数据持久化、AI 调用、骰娘运行时装配与自动更新。

入口：[main.js](file:///workspace/src/main/main.js)（`package.json` 的 `main`）。

## 1. 入口与生命周期

### 1.1 数据目录解析 `resolveDataDir()`

按运行形态决定 `data/` 位置（[main.js#L14-L22](file:///workspace/src/main/main.js#L14-L22)）：

| 形态 | 判定依据 | 数据目录 |
| ---- | ---- | ---- |
| 便携版 | 环境变量 `PORTABLE_EXECUTABLE_DIR` | `<便携解压目录>/data` |
| 绿色版 | `app.isPackaged` 且 exe 旁存在 `data/` | `<exe 同级>/data` |
| 安装版 | `app.isPackaged` 且无旁置 `data/` | `app.getPath('userData')/data` |
| 开发态 | 未打包 | 仓库根 `data/` |

安装版数据放在用户目录，与安装位置解耦，NSIS 原地覆盖升级不会触碰数据。

### 1.2 旧数据自动迁移 `autoMigrateLegacyData(target)`

安装版首次运行时，若用户目录尚无数据、而 exe 旁存在旧 `data/`，则递归复制迁移，避免「覆盖安装后内容丢失」（[main.js#L36-L46](file:///workspace/src/main/main.js#L36-L46)）。

### 1.3 初始化顺序

```
main.js 顶部（模块加载即执行）
  ├─ dataDir = resolveDataDir()
  ├─ runlog.init(dataDir)              # 运行日志
  ├─ autoMigrateLegacyData(dataDir)    # 旧数据迁移
  ├─ store = new DataStore(dataDir)    # 数据存储
  ├─ doc = store.load()                # 读取文档
  │    ├─ 补全 fields / activeProfileId
  │    ├─ 注入内置卡片模板 BUILTIN_TEMPLATES（coc/dnd）
  │    ├─ 补全 AI 开关 settings.ai（总开关 + 分开关 + 概率）
  │    └─ 补全提示词 settings.prompts
  ├─ 初始化 promptHub / exporter / diceStorePort / diceWorkbench
  ├─ pluginHost = createPluginHost({ dir })   # 插件宿主
  └─ registerIpc()                     # 注册全部 IPC
app.whenReady() → createWindow() 单窗口，contextIsolation + preload
```

关键初始化对象：

- `store: DataStore` —— 数据读写、档案、备份、快照（见 [06](06-数据存储与持久化.md)）
- `pluginHost: PluginHost` —— 骰娘规则插件安装/启停/回滚
- `diceWorkbench` —— `createDiceRuntime(...)` 产物，装配 hub + 三通道 + 日志/文案
- `updater` —— GitHub Releases 自更新（见 [08](08-自动更新机制.md)）

## 4. 骰娘运行时装配 `dice-runtime.js`

`createDiceRuntime({ store, ai, transformReplies, cfg })` 返回骰娘工作台运行时，是主进程连接内核与界面的关键枢纽：

```js
const stateBox = createStateBox();                 // 会话状态（logs/persona/sessions/users）
const hub = createHub({ store, ai, transformReplies });
const adapters = createChannelAdapters({ state: stateBox, cfg, store, hub });
for (const a of adapters) hub.attach(a);           // sim / onebot11 / qqofficial
hub.onEvent(collectLog);                            // 采集指令日志（按 msg.id 合并回显）
```

对外能力（供 IPC 使用）：`netList / netStart / netStop / status / logQuery / logExport / replyLoad / replySave / replyImport / simSend`。

指令日志以 hub 事件流为**单一数据源**：`message` 事件先占位、`replies` 事件带最终回显压入，按同一条消息 id 合并，避免一条指令出现两行。

## 5. AI 回复增强 `dice-enhance.js`

作为 `transformReplies` 注入 hub，在回复发出前二次加工：

- **骰点文本优化**：命中 `r/rd/ra/rh` 指令时，结合开团场景把结果润色得更有剧情感。
- **随机插话**：以可配置概率追加骰娘插话。

安全约束（`acceptableOptimize`）：AI 追加描述必须与引擎数值一致，拒绝「索要结果」话术与夹带伪指令；引擎原文永远先发、不被改写。受 AI 总开关与 `optimize`/`interject` 分开关约束，关闭时直接跳过、不消耗 token。
