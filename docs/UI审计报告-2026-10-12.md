## 反模式裁决（先回答最敏感的问题）

**这份 UI 读起来不像 AI 生成的。** 没有渐变文字、没有无意义光晕、毛玻璃只用在顶栏与遮罩等功能位、按钮是素净的原生形态；五套主题各有命名与气质（残火纪·暗黑 / 现代卷宗 / 极简浅色 / 赛博霓虹 / 暮光护眼），视觉方向是有意为之而非模板套壳。**通过。** 仅有两处 z-index 魔数（9999/99999）脱离了自己 2~500 的层级体系，属于毛刺不是套路。

## 发现清单（按严重度）

### P1-1 全部表单标签未程序化关联输入框
- **位置**：全库 `<label>` 121 处，`for=` / `aria-labelledby` / 包裹式关联计数 **0**（app.js 模板、index.html L148-183、views/）；典型如设置页 AI 长文本参数区 [app.js L5140](file:///workspace/src/renderer/app.js#L5140-L5144)
- **类别**：Accessibility ｜ **标准**：WCAG 1.3.1 / 3.3.2 / 4.1.2
- **影响**：视觉用户靠邻近排版能对上号，读屏用户在设置页、AI 抽屉、弹窗表单里听到的是一串无标签输入框
- **建议**：抽一个「表单行」生成函数统一输出 `for=`/`id` 配对（UICraft `extract` 工作流），存量用脚本批量补
- **Suggested next workflow**: extract — 统一 label-input 关联模式

### P1-2 toast 与 AI 处理中提示条对读屏不可感知
- **位置**：[app.js L500-L506](file:///workspace/src/renderer/app.js#L500-L506) `toast()` 仅设 className/textContent；`.ai-busy`（styles.css L427，注释自称「模态里也能看见」）同样无 live 语义；全库 `aria-live`/`role="status"` 计数 **0**
- **类别**：Accessibility ｜ **标准**：WCAG 4.1.3
- **影响**：保存/删除/导入成功、AI 开始与结束、错误提示——读屏用户全部静默
- **建议**：给 `#toasts` 容器加 `aria-live="polite"`、`.ai-busy` 加 `role="status"`；错误类 toast 用 `role="alert"`
- **Suggested next workflow**: interaction-design — 反馈通道

### P1-3 弹窗无焦点圈闭与恢复
- **位置**：`aria-modal`/`inert`/焦点恢复逻辑全库计数 **0**；打开时自动聚焦首字段有做（[app.js L2554](file:///workspace/src/renderer/app.js#L2554-L2563)），Esc 关闭闭环完整（[app.js L605](file:///workspace/src/renderer/app.js#L605)）
- **类别**：Accessibility ｜ **标准**：WCAG 2.4.3
- **影响**：键盘用户 Tab 会走进遮罩背后的内容；关闭后焦点不回触发按钮，上下文丢失
- **建议**：模态打开时 focus trap + 背景容器 `inert`，关闭时 `focus()` 回触发元素
- **Suggested next workflow**: interaction-design — 覆盖层焦点管理

### P2-1 14 处可点击元素不是原生按钮
- **位置**：app.js 模板中 div/span/td/li 挂 `onclick` 共 14 处（其余 300+ 处均为 `<button>`，值得肯定）
- **类别**：Accessibility（键盘不可达、无 role）｜ **建议**：换成 button 或补 `tabindex=0`+`role`+键盘回车处理；优先改 `td` 行点击类
- **Suggested next workflow**: harden — 键盘可达性

### P2-2 全局搜索每键全量重绘、无防抖
- **位置**：[_gPaint() app.js L6006-L6065](file:///workspace/src/renderer/app.js#L6006-L6065)，入口 [index.html L82](file:///workspace/src/renderer/index.html#L82) `oninput` 直连
- **类别**：Performance ｜ **影响**：检索索引已缓存（[app.js L3136](file:///workspace/src/renderer/app.js#L3136-L3141)），但每次按键仍整块重建结果 DOM；数千卡+长关键词时输入发涩
- **建议**：输入 120~200ms 防抖 + 结果渲染 diff（或仅重排 top N）
- **Suggested next workflow**: optimize — 输入链路

### P2-3 小型操作按钮目标约 24px
- **位置**：styles.css L263（`padding:3px 8px;font-size:11.5px`）、L341（`padding:3px 10px`）等小按钮族
- **类别**：Responsive/输入精度 ｜ **影响**：鼠标下勉强，触屏/高 DPI 笔记本触控板误触率高
- **建议**：小按钮统一最小命中区 32×32（padding 扩到 6px 或伪元素扩区）
- **Suggested next workflow**: harden — 目标尺寸

### P2-4 命令面板输入框焦点环被抹除
- **位置**：styles.css L756 `.pal-input input{outline:none;border:none}` 无替代焦点样式
- **类别**：Accessibility（WCAG 2.4.7）｜ **建议**：给容器加 `:focus-within` 高亮
- **Suggested next workflow**: interaction-design — 焦点可见性

## 系统性模式（结构性缺口，非孤立失误）

1. **辅助技术语义是「补丁式」而非「生成式」**：index.html 手写部分语义良好（aria-hidden 图标 48 处），但 app.js 生成的海量界面 aria 属性仅 3 处——模板生成器层面没有语义规范，导致 P1 三连与 P2-1。
2. **性能投入集中在热路径**：检索索引缓存、交叉引用代数缓存、大列表窗口化都做得很到位（还配了 bench 设施），但**输入事件层**（防抖）与**动效属性选择**（width 过渡）是两个没人管的夹层。

## 做得好的（保持并推广）

- **语义骨架**：header/nav/main/aside/details-summary 用得规范，`lang="zh-CN"`，图片 6 处全部有 alt（含装饰图 `alt=""`+aria-hidden）
- **Esc 闭环**：弹窗/命令面板/全局搜索/菜单/抽屉全覆盖，且快捷键先判输入域再处理（[app.js L11143-L11159](file:///workspace/src/renderer/app.js#L11143-L11159)）
- **反馈闭环**：原生 `alert()` 全库清零（统一应用内确认框）；全局 AI 处理中提示条防重复提交
- **性能设施**：大卡片列表窗口化渲染（[app.js L2073-L2168](file:///workspace/src/renderer/app.js#L2073-L2168)）、`npm run bench` 可复测热路径
- **主题工程**：data-theme 五主题 + 收敛层统一 shadow/radius；`:focus-visible` 全局 color-mix 焦点环；`prefers-reduced-motion` 全局压缩到 0.001ms
