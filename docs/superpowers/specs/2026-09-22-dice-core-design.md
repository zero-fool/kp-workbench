# 自研骰娘内核（dice-core）设计文档

- 日期：2026-09-22
- 状态：已与需求方逐段确认（架构/数据流/插件/界面/交付五段均获批准）
- 对应版本：v3.0.0（自研骰娘内核首个版本）
- 关联文档：docs/design-map-v2.md、docs/design-comfort-2.9.md、docs/design-scenario-batch-2.9.md

## 1. 背景与目标

当前「连 QQ 的骰娘」能力由内嵌第三方内核（resources/dice-next/，含 dice-next.exe 与 lagrange/milky 协议端，约 149MB）提供，.kp 数据联动寄生于其插件宿主（bridge/kp-workspace-bridge.js）。这带来三个问题：

1. 品牌与代码层面存在第三方内嵌（「海豹」行为），不符合全自研产品定位；
2. 未签名 exe 被系统安全软件拦截（此前已发生），随包维护成本高；
3. 绿色版体积 206MB，其中绝大部分是第三方产物。

目标：以**完全自研的骰娘内核**替换第三方内嵌，交付「一个完整骰娘软件 + GM 工作台」的一体应用。可以参考市面骰娘软件的功能面，但**不照搬**任何第三方的代码、插件包、台词、人设与品牌。

## 2. 已定决策（澄清记录）

| # | 议题 | 决定 |
|---|---|---|
| D1 | 通道自研边界 | 方案乙：骰娘大脑全自研；QQ 个人号走 OneBot 11 开放标准接入（用户自备合规协议端，不随包捆绑任何第三方程序）；QQ 官方机器人（腾讯公开 API）自研适配；不逆向 QQ 私有协议 |
| D2 | 指令功能范围 | ①核心组 ②情趣组 ③管理组 ④工作台联动组 全部进第一版 |
| D3 | 通道覆盖 | OneBot 11 服务端 + QQ 官方机器人客户端 + 应用内测试模拟器，三个都做 |
| D4 | 原创边界 | 指令语法沿用社区通行写法（.r/.ra/.st/.jrrp/.help 等，属行业惯例）；回复文案、人设、界面命名、帮助文档、图标全部原创重写；解析器与扩展指令体系自研 |
| D5 | 规则插件能力上限 | 乙档：纯声明式数据包 + 受限表达式（calc/ 自研沙箱求值），不接受任何可执行脚本；AI 只被允许产出「数据 + 受限表达式」 |
| D6 | 内核宿主形态 | 方案一：进程内自研内核库（纯 JS，跑在 Electron 主进程 worker 线程），无任何独立可执行文件 |

## 3. 非目标

- 不自研 QQ 个人号私有协议端（高封号风险、维护成本不可控）。
- 不做任意脚本插件（丙档）；不兼容任何第三方骰娘的插件包格式。
- 不改动 GM 工作台既有业务功能（剧情/卡牌/地图等），只把数据接口从 HTTP 桥换成同进程直连。
- 不迁移第三方内核的存量数据（data/、plugins.db 等随退役删除）；工作台自身数据（人物卡、投骰历史、档案）原样保留。

## 4. 架构：dice-core 内核库结构

自研内核 `src/dice-core/`，纯 JS、零 Electron 依赖、零第三方库，可整体搬去任何 Node 环境。依赖方向单向：`brain → rules → calc/expr`；一切对外能力只经 `ports/` 进出。

```
src/dice-core/
├─ expr/        骰子表达式引擎：词法/语法树/求值（NdM、取高取低 kh/kl、爆炸、隐骰、双骰）
│   └─ rng.js   可种子随机源（可复现、可测试）
├─ calc/        受限表达式求值器：插件携带的规则计算跑在这里（沙箱、无 IO 无副作用）
├─ rules/       判定模型：检定（普通/困难/极难/极限/对抗）、成长、成功率分档
│               内置三套规则（通用/CoC 7th/DnD 5e）是 3 个数据包，与插件同格式
├─ plugin/      规则插件宿主：包格式、结构校验、热加载、启停/回滚
│   └─ ai-author.js  AI 生成管线：规则文本 → 提示词 → 产出插件包 → 校验失败回喂修正
├─ brain/       指令大脑：
│   ├─ cmd/     指令解析与分发（别名表、参数解析），指令①②③④各为指令模块
│   ├─ reply/   原创文案库（模板 + 变量插值 + 人设），用户可编辑
│   ├─ perm/    权限（群/角色/黑白名单）
│   └─ state/   会话状态（人物卡、好感、今日运势、投骰记录）
├─ hub/         消息总线：统一消息模型进 → 会话路由（多群隔离）→ 回复出
└─ ports/       对外接口契约：
    ├─ ChannelAdapter    通道适配器接口（收发消息）
    ├─ WorkspaceDataPort 工作台数据接口（.kp 指令经此读写，替代 HTTP 插件桥）
    ├─ StorePort         持久化接口（Electron 侧给实现）
    └─ AiPort            AI 调用接口（规则插件生成、AI 骰娘对话走这里）
```

三条通道（OneBot 11 服务端 / QQ 官方机器人客户端 / 应用内模拟器）是 `ChannelAdapter` 的三个实现，放在 `src/dice-net/`，由主进程装配，内核本身不知道网络与 Electron 的存在。

每个指令模块统一接口：`handle(ctx, args) → reply`；ctx 含会话、发送者、权限、工作台数据端口、随机源。新增指令即新增一个文件。

### 4.1 ports 契约

- `MessageIn {id, channel, guildId?, groupId?, user:{id,name,role}, text, ts}`（归一消息模型）
- `ReplyOut {sessionId, segments[], at?}`（结构化回复，按通道格式化）
- `CommandContext {session, sender, perm, data:{workspace, cards, state}, rng, ai}`
- `ChannelAdapter {id, start(), stop(), onInbound(cb), send(sessionId, reply), status()}`
- `WorkspaceDataPort {list/get/create/update/remove(kind, …), audit()}`，kind ∈ pcs/npcs/regions/logs/mobs
- `StorePort {load(key), save(key, value), backup()}`
- `AiPort {chat(cfg, messages, signal)}`（可取消）
- `RulePlugin {manifest, dice, checks, cardFields, commands, templates}`（见第 6 节）

## 5. 数据流与指令生命周期

```
通道(OneBot11 / QQ官方 / 模拟器)
   ↓ ChannelAdapter 收到 → 归一成 MessageIn
hub/ 消息总线：按「通道+群/私聊」路由到会话（多群状态完全隔离）
   ↓
perm/ 权限闸（黑白名单、管理指令校验）
   ↓
brain/cmd/ 解析：前缀识别 → 别名展开 → 参数解析 → 分发指令模块
   ↓ handle(ctx, args)
   ├─ expr/calc/rules：掷骰与判定（过 rng，结果带完整过程明细）
   ├─ state/：人物卡/好感/运势/记录（同会话写操作串行化）
   ├─ WorkspaceDataPort：.kp 指令同进程内存直读直写工作台数据
   └─ AiPort：AI 对话/定向判定（可取消，不影响其他指令）
   ↓ 返回结构化结果
reply/ 文案渲染：结果模板 + 变量插值 + 人设 → ReplyOut
   ↓
hub/ 按来源通道格式化 → ChannelAdapter.send
   ↓（旁路）各环节事件同步给界面：指令日志面板实时可见
```

关键设计点：

- **`.kp` 联动降级为函数调用**：插件→HTTP→dice.js 的桥整条删除，`WorkspaceDataPort` 由主进程直接实现，改数据立即触发界面刷新。
- **投骰可复现**：每条掷骰记录存「表达式 + 随机种子 + 过程明细」，历史可回放审计。
- **故障隔离**：单条指令出错只回一条友好错误，不炸会话、不影响其他群；AI 超时可取消，掷骰与检定永不依赖 AI。
- **状态持久化**：人物卡/记录/文案/插件启停走 `StorePort`，写应用数据目录，沿用现有备份机制。
- 指令前缀默认 `.`，可在管理组设置中改（含全角 `。` 兼容开关，默认开）。

## 6. 规则插件体系 + AI 生成管线（乙档能力）

插件包 = 一个 JSON 数据包（无可执行代码），装在 `data/dice-plugins/<插件id>/`。示例结构：

```json
{
  "manifest": { "id": "demo-system", "name": "示例规则", "version": "1.0.0",
                "ruleset": "自定义", "author": "插件作者名", "minCore": "3.0" },
  "dice":      { "常用骰式": "1d100", "取优": "2d20kh1" },
  "checks":    [ { "name": "技能检定", "expr": "1d100",
                   "levels": ["大成功", "极难成功", "困难成功", "成功", "失败", "大失败"],
                   "calc": [ { "name": "分档",
                               "expr": "if(R<=5,'大成功', R<=skill/5,'极难成功', R<=skill/2,'困难成功', R<=skill,'成功', R>=96,'大失败', '失败')" } ] } ],
  "cardFields": [ { "key": "san", "label": "理智", "type": "number", "default": 50 } ],
  "commands":  [ { "trigger": "build", "alias": ["建卡"],
                   "run": "calc: '属性生成：力量' + str(roll('3d6')*5) + '，敏捷' + str(roll('3d6')*5)" } ],
  "templates": { "checkResult": "{name} 做出「{skill}」检定：掷出 {roll} → {level}" }
}
```

### 6.1 受限表达式沙箱（calc/）

自研求值器，能力白名单：数值/字符串/布尔、四则与比较运算、`if` 条件、骰式调用 `roll('3d6')`、人物卡字段引用、局部变量、函数白名单（round/min/max/floor/ceil/abs）。**无 IO、无全局访问、无自定义函数定义**；执行步数上限 10,000、表达式深度上限 32、单次骰式上限 100 骰 1000 面；越界即拒绝并报出字段路径与位置。插件里所有 `calc:` 片段均在此求值。

### 6.2 生命周期

1. **生成**：用户喂规则文本（粘贴 / 导入文档）→ `ai-author.js` 用现有 AI 配置（OpenAI 兼容端口）生成插件包 → 结构校验失败时把结构化报错**回喂 AI 修正，最多 3 轮**。
2. **准入**：生成后先进**测试通道试跑**（第 7 节分区 6），跑指令看结果，用户确认才安装（两道闸）。
3. **安装/管理**：热加载即用；界面支持启停、编辑 JSON、导出分享、一键回滚上一版；内置三套规则同格式，可复制为模板修改。
4. **生效形态**：装上后出现在规则选择中，`ra`/`st`/自定义指令直接可用，结果措辞沿用插件 templates（用户可再改）。

### 6.3 安全边界重申

AI 提示词设计只产出「数据 + 受限表达式」；校验器按白名单字段过滤，未知字段直接剔除；校验器配「恶意包样本集」回归（越权字段/死循环表达式/超大骰式必须全拒）。

## 7. 界面整合与旧内核退役

骰娘板块升级为「骰娘工作台」，六个分区（沿用现有 UI 风格）：

1. **投骰台**：现有本地投骰面板保留并升级，本地投骰与群里指令换用同一个 dice-core 引擎，规则插件对两端同时生效。
2. **连接中心**：三通道接入向导（OneBot 11 地址/Token 配置、QQ 官方机器人凭据、模拟器启动）、状态灯、断线重连提示。
3. **指令日志**：实时滚动显示各会话进出消息、命中指令、掷骰明细，可筛选/导出（取代原 Web 控制台）。
4. **文案与人设**：文案库可视化编辑（回复模板/人设/帮助文案），改完即生效，可导出分享。
5. **插件工坊**：规则插件管理（列表/启停/编辑/回滚/导出）+ AI 生成向导（喂规则文本 → 生成 → 测试通道试跑 → 准装）。
6. **测试通道**：内置聊天窗，模拟玩家身份喊指令，全部功能离线可测。

与 GM 工作台互通：`.kp` 数据实时双向刷新（数据源换同进程直连）；AI 端口配置共用；本地投骰历史与群里投骰记录并档可查。

旧内核退役（一次干净移除）：

- 删 `resources/dice-next/`（149MB 内核 + lagrange/milky）。
- `src/main/dice.js` 砍掉 spawn/进程托管/HTTP 客户端/health/tunnel 等内核管理代码，数据存取并入主进程服务。
- `bridge/kp-workspace-bridge.js` 与 `/sd-api` 依赖整条退役，功能原生化。
- 界面删除「定位内核/引擎目录/Web 控制台」等交互；preload 的 `dice.*` 接口按新内核重写。
- 版本守卫脚本加入「零第三方依赖扫描」（防内嵌残留回流）。
- 预期绿色版体积 206MB → 约 70MB；不再存在可被拦截的可执行面。

## 8. 错误处理

- 表达式/规则错误：带行列位置的可读提示；群里回友好短句，日志面板留完整信息。
- 插件校验失败：结构化报错回喂 AI（≤3 轮）；运行期越界拒绝该片段并指明字段路径；插件可一键停用/回滚。
- 通道断线：自动重连 + 状态灯；多通道互不影响，单通道故障不拖垮内核。
- AI 超时/失败：可取消、有兜底文案；掷骰与检定永不依赖 AI。
- 指令异常：捕获后回友好错误（原创措辞），会话与其他群无感。

## 9. 测试策略

- 单测：expr/calc 用种子随机源做可复现断言；插件校验器跑恶意包样本集。
- 集成：用测试通道把 ①②③④ 全指令跑成回归用例，每次改动全量重放。
- 联调：OneBot 11 用自写假协议端打真实消息流；QQ 官方通道走腾讯沙箱环境。
- 沿用 `tools/` 接线审计与版本守卫，新增零第三方依赖扫描。

## 10. 交付节奏（三期，每期独立可验收）

- **M1 内核库 + 指令①核心组**：expr/calc/rules/brain/hub/ports 成形；掷骰表达式、CoC/DnD 检定、帮助、人物卡指令可用；本地投骰换新引擎；测试通道可玩。
- **M2 通道 + 指令②③**：OneBot 11 与 QQ 官方双通道真实收发；今日运势/签到/随机事件/文案人设（②）与权限/会话隔离/自定义指令/记录导出（③）齐；连接中心、指令日志、文案编辑器就位。
- **M3 插件工坊 + 指令④ + 退役**：AI 生成规则插件管线（乙档）；`.kp` 原生化（工作台联动、AI 骰娘对话）；旧内核/桥插件全删；瘦身打包绿色版。

## 11. 验收标准

1. 全部指令（①②③④）在测试通道跑通并留有回归用例。
2. OneBot 11 与 QQ 官方通道能真实收发消息并回掷骰结果。
3. AI 能从规则文本生成出可安装、可用的规则插件（乙档），装坏可回滚。
4. `.kp` 群指令与 GM 工作台数据实时联动正常。
5. 交付物零第三方可执行文件、零第三方品牌/台词痕迹；绿色版打包通过且无可被拦截面。
6. 工作台既有功能回归全绿（沿用版本守卫 + 接线审计）。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| OneBot 11 协议端生态变动 | 只依赖公开标准协议面，接入向导可配置地址/Token，不绑定任何具体协议端实现 |
| QQ 官方 API 变更/审核 | 走腾讯公开文档与沙箱；通道独立，故障不影响其他通道 |
| AI 生成插件质量不稳定 | 生成→校验→试跑→准装四步闸 + 回喂修正上限 + 一键回滚 |
| calc 表达式能力不足以覆盖个别奇葩系统 | 白名单函数可扩展；极端需求留到后续丙档评估，本期不做 |
| 大范围重写引入回归 | 三期分期交付、每期全量回归；旧内核在 M3 前保持可回退（分支隔离） |
