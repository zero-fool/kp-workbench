# 地图功能设计文档（DnD / 参照枭熊 · Owlbear Rodeo）

- 日期：2026-09-08
- 版本：v0.1（设计评审稿）
- 状态：待用户评审通过后进入实现

## 1. 背景与目标

在 KP 跑团工作台中新增一个**地图画板**功能，参照开源轻量虚拟桌面"枭熊 Owlbear Rodeo"的地图优先、免登录查看、网格/标记/迷雾交互体验，让 KP 能导入地图、布置标记、管理迷雾并本地查看。联机（1 KP + 多 PL 同屏看地图）本轮**仅做可行性分析，不实现**。

## 2. 范围界定

### 本轮实现（In Scope）
- 多地图列表资料类型管理（新增为第 8 类资料 `maps`）。
- Canvas 地图画板：底图导入、网格、拖拽标记（内置多类）、迷雾涂抹/擦除、缩放/平移。
- AI 设计地图：由文本/图片素材生成"底图规格 + 标记/区域/迷雾要素"，**预览后确认**才写入画板。
- 数据随工作台 `persist()` 持久化，随资料导出/导入。

### 本轮不做（Out of Scope）
- 联机（KP/PL 同屏）：仅输出可行性分析结论。
- 真正接入第三方生图接口生成真实地城画面（只预留扩展点，先内置占位底图）。

## 3. 参照物确认

用户确认参照物为 **Owlbear Rodeo（开源、地图优先、玩家点链接即加入同屏查看、带网格/迷雾/标记/骰子）**。取其"轻量、地图优先、只读跟随"的交互精神，不复制其代码/依赖（与本应用严格本地 CSP 冲突）。

## 4. 解决方案选择

### 4.1 画板实现
选 **方案 A · 自研 Canvas 地图画板**（推荐）：
- 纯本地渲染，契合现有 CSP（仅 `self`/`data:` 资源）。
- 嵌入现有侧栏导航与持久化体系，地图作为新资料类型平级管理。
- 由现有 IPC 加载本地底图，数据存 `data/maps/`。
- 备选 B（内嵌枭熊 Web 版）因依赖多、CSP 冲突、改造面大不选；备选 C（复用关系网 SVG 引擎）因不适合图片底图与迷雾不选。

### 4.2 底图画面生成
选 **占位底图 + 预留生图扩展点**：
- 当前：AI 仅生成"地图规格"（网格、标记、区域、迷雾草案），画板用内置占位底图/纯色网格承载要素。完全离线安全、成本为零。
- 预留：数据模型含 `imgKind`（`placeholder` / `generated` / `uploaded`）与底图引用字段，将来接入生图接口只需新增一个"生成真实底图"通道。

### 4.3 AI 素材来源
选 **面板内选材**：地图面板直接提供粘贴文本输入框 + 选择已导入文本/图片素材的入口，复用现有 AI 通道。

## 5. 数据模型（第 8 类资料 `maps`）

```jsonc
{
  "id": "map-xxx",
  "name": "地城一层",
  "img": "os-a1b2c3.jpg",        // 底图文件，存 data/maps/
  "imgW": 1920, "imgH": 1080,    // 底图原始尺寸
  "imgKind": "placeholder",      // placeholder | uploaded | generated（预留生图）
  "grid": { "on": true, "size": 64 },
  "markers": [
    { "id": "mk-1", "type": "mob", "label": "食尸鬼", "x": 320, "y": 180 }
  ],
  "fog": [
    { "path": [[0.1,0.2],[0.3,0.15],[0.5,0.3]] }  // 迷雾多边形，坐标规范化为 0~1
  ],
  "note": ""
}
```

**内置标记类型**（五类，与现有 `DATA_TYPE` 平级，各配颜色/图标）：

| type | 含义 | 建议配色/图标 |
|---|---|---|
| mob | 怪物 | 红 / 骷髅 |
| npc | NPC | 蓝 / 人头 |
| plot | 剧情点 | 紫 / 星星 |
| exit | 入口/出口 | 绿 / 箭头 |
| area | 区域块 | 金黄 / 方框标注 |

坐标规则：`markers` 用底图真实像素（缩放不漂移）；`fog` 用规范化比例（多屏比例一致）。

## 6. 界面与交互

侧栏"工具"区新增「地图」入口 → 默认展示**地图列表**（卡片式，含新增/删除）→ 点入某张进入**画板视图**（沉浸式，隐藏侧栏）。

```
画板视图（满屏）
 ├─ 顶栏：返回列表 · 地图名 · 网格开关 · 迷雾开关
 ├─ 浮层工具栏：选择/拖拽 · 添加标记(选类型) · 涂抹/擦除迷雾 · 缩放+/-/适应窗口 · 删除标记
 └─ 主画布：Canvas 渲染 底图 → 网格 → 标记 → 迷雾遮罩；滚轮缩放、拖拽平移
```

交互要点：
- 导入底图后自动铺满并显示网格；标记拖拽并对齐网格。
- 迷雾：涂抹揭露 / 擦除遮蔽，存为路径数据。
- 全部修改随 `persist()` 自动保存。
- 滚轮缩放与平移为主打手感，实现时重点打磨。

## 7. AI 设计地图（预览后确认）

在画板视图新增「AI 设计地图」面板（浮层）：

```
素材来源：粘贴文本 · 选择已导入文本/图片素材 · 当前选中资料卡
输出类型：底图规格（占位）+ 要素（网格/标记/区域/迷雾草案）
[生成] → 调用现有 AI 通道（复用已配置 AI）
预览区：小图缩略 + 要素清单（几类标记、区域、迷雾轮廓）
操作：[采纳此版] / [重新生成] / [取消]
  · 采纳 → 应用到画板并 persist()
  · 重新生成 → 再调一次 AI 换一版
  · 取消 → 丢弃
```

原则：
- AI 一次性返回结构化地图定义（JSON：底图规格、网格建议、标记列表、区域多边形、迷雾草案）。
- 只渲染为可编辑的预览，不直接污染当前画板。
- 只有点「采纳此版」才写入地图资料并持久化。
- 复用现有 AI 配置与素材导入逻辑；素材来源自动取当前选中卡 / 已导入文本。

## 8. 联机可行性分析（仅评估，不实现）

目标：KP 端工作台上，PL 免登录同屏看地图（1 KP + 多 PL）。

### 8.1 推荐架构
- **KP 本地 WebSocket 中继**：由 Electron 主进程起一个本地 WebSocket 服务，作为地图状态的权威源。
- **PL 免登录浏览器加入**：KP 端生成短链接 / 房间码，PL 用浏览器打开即加入同屏跟随，对应枭熊"点链接即入"模型。
- 权限：KP 拥有编辑/迷雾权限；PL 只读跟随（可见性由迷雾覆盖）。编辑状态经 WebSocket 广播给所有 PL 客户端。

### 8.2 部署取舍
| 部署 | 说明 | 成本/复杂度 |
|---|---|---|
| 本机/局域网 | KP 端局域网内可直接访问本地服务 | 低；同房间 Wi-Fi 场景即可用 |
| 跨公网 | 需自建中继服务器或 TURN/STUN | 中高；涉及公网部署、鉴权与带宽 |

### 8.3 结论
- **完全可行**，B/S 独立通道与现有桌面端解耦，不破坏本地数据与 CSP。
- 局域网场景成本低，可作为后续迭代；跨公网需额外基础设施，建议作为独立子项目单列评估。
- 本轮不实现，仅保留结论供后续规划。

## 9. 错误处理
- 底图加载失败：提示并回退占位底图，不破坏已有标记/迷雾数据。
- AI 生成返回非法 JSON：捕获解析错误，给出"重新生成"，不写入画板。
- 迷雾坐标越界/异常：规范化时裁剪到 0~1 区间并丢弃非法段。
- 持久化失败：提示用户，保留内存态待下次保存。

## 10. 测试要点
- 画板缩放/平移在极端底图尺寸（如 4096px 长图）下位置不漂移。
- AI 生成后"采纳/取消/重新生成"三态行为正确，采纳才落盘。
- 导出/导入含 `maps` 资料与底图文件后重载完整。
- 多种标记类型与迷雾叠加渲染正确。
