# 2.9.x 批次设计 · 三档全量推进（方案 C）

> 状态：已获用户确认（2026-09-18）。本批覆盖三大方向：临场玩法工具（全新）、AI 深度增强、数据可视化升级，外加可用性/发布收尾。采用 A/B/C 三档逐版推进的均匀路线。

## 1. 目标与定位

2.8.x 是性能优化批次收尾（增量渲染 / 差量写盘 / 事件委托）。本批 2.9.x 在既有功能完整的基础上，做一轮「新功能 + 深化 + 收尾」：
- **A 档**：填补完全空白的临场玩法（战斗/遭遇 记录与追踪），给到真正的临场价值。
- **B 档**：把 AI 从「记录助手」推向「创作大脑」，并补全总览可视化。
- **C 档**：补齐「好用、可交付」的最后一公里，打通自动更新并全量回归发布。

三档相对独立、主题聚焦，正好一版一个主题，符合方案 C 均匀推进的意图。

## 2. 分版本范围

### 2.9.0 — A 档（主线）：临场玩法工具 + 少量可视化

全新功能面，优先给到临场价值。新增一处视图，并复用现有骰娘/日志数据。

| 功能块 | 内容 | 依赖 |
|--------|------|------|
| 遭遇战/战斗记录 | 新建一场遭遇，登记参战单位；复用现有 NPC/怪物/PC 卡直接拉入 | 资料卡 `pcs/npcs/mobs` |
| 回合追踪器 | 回合顺序、当前行动者高亮、一键「下回合 / 跳过」，顺序可拖拽微调 | 遭遇记录 |
| 血量/状态追踪 | 每单位 HP 增减、状态标记（中毒/狂暴/昏迷/血流…），状态以胶囊展示 | 遭遇记录 |
| 投骰即记 | 骰娘投掷结果一键记入当前遭遇与日志，形成临场流水 | 骰娘 + 日志 `logs` |
| 少量可视化 | 遭遇内血量/状态速查条 + 投骰结果历史并入总览 | 上述数据 |

**范围控制（防过度工程）**：查看/回合/血量状态作为「可选的遭遇流程」实现——若遭遇为空或未开启追踪，则不触发回合/状态特性；回合追踪与状态追踪可独立开启/关闭，避免为全量 encounter 建立复杂状态机。

| 叙事风格贴合 | 强化人设与偏好注入，续写时贴合既有文风 | AI 设定 + 用户偏好 |

可视化补全（总览看板升级）：
| 图表 | 内容 |
|------|------|

## 3. 架构与数据设计

- 新增一类持久化数据 `encounters`（遭遇），与既有 7 类实体并列，纳入 `KIND_LIST / NAME / NAME_FIELD`，支持增量写盘与快照。
- 遭遇内部结构：
  - `sessions`：多场遭遇列表
  - `units`：参战单位（引用现有卡 id + 临场 HP/状态快照）
  - `flow`：回合顺序（有序单位 id 列表）
  - `combatLog`：投骰/行动流水
- AI 落地回滚：与现有 `AI 落地记录` 同一机制，A/B 档 AI 产物统一可回滚。
- 可视化：复用总览看板面板机制，新增可隐藏的分析面板；数据复用既有计数/投骰/剧本统计。

## 4. 错误处理与测试

- 遭遇引用已删除卡：显示「已移除」占位并允许剔除，不崩溃。
- HP/状态不做复杂规则引擎；输入非法数值走 UI 校验拦截。
- 新功能均补回归断言（`tools/regress.test.js`），关键模块加 `npm run bench` 基准复测（若引入热路径）。
- C 档打包链路按 `DEPLOY.md` 三文件（安装版 .exe + .blockmap + latest.yml）验证。

## 5. 范围之外（YAGNI）

- 不引入实时联机 / 多玩家同步。
- 不做完整职能（角色扮演系统 / 完整战斗规则引擎）；本批只做「记录 + 追踪」工具的临场辅助。
- 不做 AI 语音 / 图像识别能力。

## 6. 发布配套

每档交付时更新 `package.json` 版本号、`APP_VERSION`、`CHANGELOG` 公告条目；C 档整体走 `build:update` 产出三文件作为更新源。
